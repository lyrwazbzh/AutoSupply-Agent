# 能力地图与主链

本项目是面向新能源汽车整车制造的采购 / 供应链 Agent：DeepSeek 驱动 Deep Agents + LangGraph，经 MCP 访问 Java ERP，本地工具在用户沙箱里出图、出文档，Harness 把一次请求标成 Planning → Executing → Review → Result。

代码入口：`src/api_view/web_main.py`（HTTP）、`src/agent/main_agent.py`（图装配）、`src/mcp_server/server_main.py`（ERP 网关）。前端 `frontend/` 不在本学习主线。

后面出现 `create_main_agent`，就是给某个用户装好可 `astream` 的图。出现 `load_mcp_tools_sync`，就是把 ERP 工具袋并进主 Agent。出现 `task(subagent_type=...)`，就是委派四个 YAML 子 Agent 之一。

---

## 1. 解决什么问题

采购分析要同时查 MRP / BOM / 供应商、画图、写报告、偶发写订单。直接把浏览器请求绑死在一次同步 LLM 调用上，无法中断审批、无法按用户隔离代码执行、也无法把 ERP 路径细节塞进提示词。系统拆成入口、会话 Agent、工具桥、沙箱和记忆，各管一段。

## 3. 核心设计与实现

进程两套：`uvicorn` 跑 FastAPI；另起 `server_main.py` 跑 MCP SSE。Agent 默认连 `MCP_SSE_URL`（`http://localhost:9000/sse`）。

主 Agent 一次运行：checkpoint 按 `thread_id` 落 Mongo；展示消息、Harness 轨迹、委派轨迹另写 Motor 集合。沙箱按用户认领，映射也进 Mongo，进程重启可恢复容器。

四个子 Agent 来自 `procurement_analyst.yaml`、`strategic_sourcing.yaml`、`procurement_order.yaml`、`supplier_quality_risk.yaml`：计划齐套、寻源定点、交付协同、质量风险。主提示词约定何时 `task`；门禁校验注册表、并发、交接字段和回流结构。

---

## 4. 关键设计取舍

| 点 | 现行选择 |
|----|----------|
| ERP 访问 | Agent 只调 MCP 工具名，路径与 camelCase 映射在网关 |
| 代码执行 | 用户级 Docker，工具走 `sandbox_holder` |
| 完成标准 | 非闲聊请求可写入 rubric，由 `RubricMiddleware` 启 grader |
| 记忆 | HOT=checkpoint，WARM=每轮注入，COLD=`read_memory` |

---

## 5. 踩坑与解决

MCP 进程未起时 `load_mcp_tools_sync` 返回空列表，对话仍可用本地工具。沙箱预热失败时 `web_main` 仍继续启动，健康中间件随后补容器。

---

## 6. 面试问答

**和「单 Agent 调 HTTP」差在哪？**  
多一层 MCP 工具契约；图状态可中断；代码在沙箱。

**Harness 四个阶段谁写？**  
`HarnessPhaseMiddleware` 钩子写 `state.phase`；SSE 在 `chat.py` 的 values 流里比变化。

**主 Agent 和子 Agent 谁看见父对话？**  
父 `messages` 不传入子图；子只见 enrichment 后的 `description`。

## 7. 相关概念

**Harness Engineering**：阶段字段 + 可选 rubric 评审。  
**CompositeBackend**：Store 与沙箱 Shell 拼成 Deep Agents 后端。  
**HITL**：`interrupt` 挂起图，前端 resume 再跑。

**收束。** 面试开场用这条链：入口装配会话 → 图按 Harness 跑 → 工具分 MCP/本地/委派 → 沙箱与记忆托底。细节进 01～09。
