# 目录、安装与同步

Skills 是给模型看的操作手册（`SKILL.md`）加上可在沙箱执行的脚本。仓库内 `src/skills` 在 bootstrap / Sync 时进入容器 `/skills`；用户经 `install_skill` 安装的技能进宿主目录、沙箱 `/skills/custom` 与用户 Store，下次由 `UserSkillsRestoreMiddleware` 恢复。手册进 system 提示，执行面靠同步与恢复保证容器内文件就绪。

代码：仓库技能树 `src/skills/`；宿主工具 `src/agent/tools/web_fetch.py`（`web_fetch` / `install_skill`）、`skill_management.py`、`assign_skill.py`；中间件 `src/agent/middlewares/skills_sync.py`、`user_skills_restore.py`；装配与提示拼接 `src/agent/main_agent.py`（`_load_skills_prompt`、`bootstrap_sandbox`）；namespace `skills_store_namespace` 见 `src/agent/config.py`。沙箱热替换见 `08/01`；主 Agent 中间件栈见 `03/01`。

出现 `/skills/`，就是仓库基础技能在容器中的根。出现 `/skills/custom/`，就是用户安装技能在容器中的根。出现 `generation` 失效，就是 Proxy 换代后 Sync / Restore 清缓存再对齐。出现 `list_user_skills`，就是只读 Store 聚合自定义技能名。

---

## 1. 解决什么问题

采购比价、抓网页、优化库存有固定步骤，适合写成 `SKILL.md` 让模型按手册调脚本，而不是每次从零编 Python。还要把三件事拆开：

| 面 | 落点 | 谁保证就绪 |
|----|------|------------|
| 模型怎么知道有哪些技能 | system 提示里的手册全文 + name/description 摘要 | `_load_skills_prompt`（建图时从磁盘拼） |
| 沙箱里怎么跑脚本 | `/skills/...` 与 `/skills/custom/...` | bootstrap 初拷 + Sync / Restore（每次 `before_agent`） |
| 用户装的技能跨会话 / 换容器还在 | Store `("persisted-skills", user_id)` | `install_skill` 写入；Restore 读回 |

SKILL 是长手册 + 沙箱脚本；宿主 `@tool` 是 schema 固定的函数。新技能落盘并同步后即可用，不必改 `custom_tools` 列表。

## 2. 架构 / 数据流

### 2.1 目录约定

```text
宿主
  src/skills/
    main/skill-management/     # 技能管理手册 + download_skill.py
    procurement/
      web-scraper/             # SKILL.md + scraper.py …
      web-content-fetcher/
      price-comparison/
      …
    （可选独立 .md，如 chart_params）

沙箱
  /skills/                     # Sync：相对路径镜像宿主 src/skills
  /skills/custom/<name>/       # Restore / install：用户自定义

Store
  namespace = ("persisted-skills", user_id)
  key = "<skill_name>/<相对路径>"
  value = { content: base64, encoding, source }
```

标准技能包：`SKILL.md`（必有，YAML frontmatter 含 `name` 等）+ 可选 `.py` / `requirements.txt` / `assets/`。

### 2.2 请求路径里谁在何时动手

```text
create_main_agent
  CompositeBackend：/persisted-skills/ → skills_store_namespace(user)
  挂 SkillsSyncMiddleware、UserSkillsRestoreMiddleware
  system += _load_skills_prompt(src/skills)
  ↓
沙箱新建 / Health 重建
  bootstrap_sandbox：mkdir → 上传项目 → cp …/skills → /skills/
  on_rebuild：两边 invalidate → sync_now + restore_now
  ↓
每次 before_agent
  Sync：本地 src/skills 增量 → /skills/（generation 变则先清缓存）
  Restore：Store → /skills/custom/（同上）
  ↓
模型
  读提示中的手册；execute 跑沙箱脚本
  可调 web_fetch / install_skill / list_user_skills / assign_skill
```

异步路径上 Sync / Restore 的 I/O 放进 `to_thread`，避免堵 SSE 事件循环。

### 2.3 两条技能通道

| 通道 | 来源 | 容器路径 | 持久化 |
|------|------|----------|--------|
| 仓库基础技能 | 宿主 `src/skills` | `/skills/{相对路径}` | 跟仓库走；bootstrap + Sync |
| 用户自定义 | `install_skill` URL 包 | `/skills/custom/<name>/` | 宿主目录 + Store；Restore 恢复 |

## 3. 核心设计与实现

### 3.1 提示拼接：`_load_skills_prompt`

建图时手动扫 `src/skills`：所有 `SKILL.md`，以及足够长的独立 `.md`。按相对路径成节，并用正则抽 `name` / `description` 做摘要列表。段落说明：基础技能在 `/skills/`，用户技能在 `/skills/custom/`，可用 `list_user_skills` 查询。框架内置 skills 加载器对含中文/空格路径不稳，故走这套磁盘拼接。

### 3.2 Bootstrap 与热替换再灌装

**`bootstrap_sandbox`。** `mkdir` 工作区与 `/skills` → 上传项目到沙箱 → `cp -r /workspace/src/src/skills/. /skills/`（依赖项目 tar 解压后的双层 `src` 前缀）。只使用 Proxy 公开能力，重建后同一 Agent / CompositeBackend 可继续用。

**`_rehydrate_after_sandbox_rebuild`。** Health 换容器后：`invalidate` Sync 与 Restore 缓存 → 立刻 `sync_now` + `restore_now`。另有兜底：中间件在 `generation` 变化时自动 `invalidate` 再对齐。

### 3.3 Sync：宿主仓库 → `/skills/`

`SkillsSyncMiddleware`：每次 Agent 执行前增量同步。

**`sync_now`。** 技能目录不存在则返回。有 `sandbox_backend`：若 `generation` 相对上次变了，先 `invalidate`，再 `_sync_to_sandbox`，记下新 generation。无 backend（LocalShell）：`_validate_local_skills` 只扫本地 `SKILL.md` 打日志，不上传。

**`_sync_to_sandbox`。**

1. `rglob` 扫本地树，跳过 `__pycache__` / `.pyc` / `.git` 等；相对路径 → MD5  
2. 哈希与缓存不同则上传：文本 UTF-8、二进制字节，写到 `/skills/{相对路径}`  
3. 上次有、这次没有的路径，沙箱 `rm`  
4. 更新 `_file_hashes` / `_last_synced_files`

**`invalidate`。** 清空哈希与已同步集合，下次全量再传。`compute_skill_folder_hash` 把文件夹内各文件哈希拼起来再 MD5，作整包指纹。

### 3.4 Restore：Store → `/skills/custom/`

`UserSkillsRestoreMiddleware`：以「每文件一条 Store 记录」恢复。路径永远由 key 推导为 `/skills/custom/{key}`，不信任 value 里的绝对路径。

**`restore_now`。** Store 或 sandbox 缺失则返回。`generation` 变化则 `invalidate`，再 `_restore_skills`。

**`_restore_skills`。**

1. `search(skills_store_namespace(user_id))`  
2. 逐条：安全映射路径、解码内容（`encoding=base64` 或兼容纯文本 / bytes）；内容 SHA256 与缓存相同则跳过  
3. 需写入：`mkdir -p` 父目录；已有文件尽量 `.bak`；`write_file`；若是 `requirements.txt` 记入待装集合  
4. 上次恢复过、本次 Store 已无的路径从沙箱删掉  
5. 对新增的 `requirements.txt`：`pip install --target /workspace/python-packages`

**`list_user_skills`。** 只读 Store：按 key 第一段路径聚合成技能名与文件数；路径提示 `/skills/custom/<name>/`。未走 `install_skill` 持久化时列表为空。不扫磁盘、不改沙箱。

### 3.5 安装：`install_skill`（下载 → 沙箱校验 → 三处落点）

宿主 `@tool`，与沙箱内 `download_skill.py` 手册路径互补：正式安装与持久化走本工具。

**流程概要。**

1. 规范化 URL（GitHub 仓库页可转 ZIP）；空名称则从 URL 提取，非法字符换成 `_`  
2. 无沙箱则拒绝安装  
3. 下载到内存：压缩包解到 `{相对路径: bytes}`（跳过目录、`__MACOSX`、点开头；有顶层目录则剥第一层）；单文件可当成 `SKILL.md`；没有 `SKILL.md` 则取消  
4. 写入沙箱临时目录 `/tmp/_skill_install_{name}/skill/`  
5. `_validate_skill_in_sandbox`；失败清临时目录，宿主机不动  
6. 通过后三处落点：宿主 `src/skills/<name>/`、沙箱 `/skills/custom/<name>/`、用户 Store（key=`{name}/{相对路径}`，content base64）  
7. 若有 `requirements.txt`，只在沙箱 `pip install --target /workspace/python-packages`  
8. 清临时目录，返回安装结果文案  

**校验（`_validate_skill_in_sandbox`）。** 必须有可读 `SKILL.md`；frontmatter 用 `---` 包裹，`yaml.safe_load`；`name` 必填、非空、字符安全；有 `version`/`description` 则须为字符串；frontmatter `name` 与安装名不一致只打 warning。每个 `.py` 扫危险模式（`eval`/`exec`/`subprocess`/`os.system`/`pickle`/`socket` 等）→ warning，不单独因此判失败。路径含 `..` 或单文件超过 10MB → 失败。

**同文件的 `web_fetch`。** 宿主拉网页文本：协议须 http/https；`httpx`（跟重定向、超时 20s）；HTML 剥标签；超 `max_chars`（默认 8000）截断。与技能包内抓页脚本分工不同：一个给模型即时读 URL，一个给沙箱批处理落盘。

### 3.6 分配：`assign_skill`

把已有技能挂到指定 Agent 的 scope 目录。遍历 `src/skills` 下各 scope，命中 `scope/skill_name/SKILL.md` 或 `scope/{skill_name}.md`。`agent_name != "main"`：复制到 `skills/{agent_name}/{skill_name}`（已存在则提示）。`main`：不复制，确认已在主库可用。

### 3.7 技能包内脚本（沙箱执行示例）

这些脚本写在 `src/skills/...` 下，由手册指引模型在容器里 `python /skills/...` 调用；经 Sync 后路径可用。

| 脚本 | 位置（示意） | 行为 |
|------|--------------|------|
| `download_skill.py` | `main/skill-management/` | URL 下 ZIP → 解压 → 校验存在 `SKILL.md` 且 frontmatter 含 `name`/`description`/`scope` |
| `scraper.py` | `procurement/web-scraper/` | GET 网页 → BeautifulSoup：标题、正文、最多 10 表、前 50 链 → JSON（默认 `/output/scraped.json`） |
| `fetcher.py` | `procurement/web-content-fetcher/` | GET → 去噪 HTML → markdownify → 截断 Markdown（默认 `/output/content.md`） |

其它采购技能（比价、库存、供应商分析、报告等）同构：`SKILL.md` 描述步骤，可选脚本与 `requirements.txt`。`chart_params.md` 等独立 md 给图表字段约定，进提示拼接。

## 4. 关键设计取舍

| 取舍 | 现行做法 |
|------|----------|
| 基础 vs 自定义 | 磁盘 + Sync → `/skills/`；Store + Restore → `/skills/custom/` |
| 安装安全 | 先沙箱临时目录校验，再写宿主 / custom / Store；路径穿越与超大文件失败；危险模式记 warning |
| 增量与换代 | 相对路径 MD5 / SHA256 缓存；Proxy `generation` 变或 `on_rebuild` 时 `invalidate` 全量对齐 |
| 依赖安装 | 仅沙箱 `--target /workspace/python-packages`，根文件系统只读时仍可装包 |
| 提示 vs 执行 | 手册进 system；脚本进沙箱；两边靠 Sync/Restore 对齐 |

## 5. 工程边界

| 主题 | 现行行为 |
|------|----------|
| bootstrap 拷贝路径 | `cp -r /workspace/src/src/skills/. /skills/` 依赖上传解压后的双层 `src` 前缀；前缀不对则初拷缺基础技能，仍可靠 Sync 从宿主目录补 |
| `list_user_skills` | 只读 Store；仅统计经 `install_skill` 持久化的自定义技能 |
| 缓存与热替换 | 换容器后必须 `invalidate`（回调或 generation 兜底），否则旧哈希会跳过应重写的文件 |
| CompositeBackend | `/persisted-skills/` 路由到 `skills_store_namespace(user_id)`，与 Restore 同一用户隔离 |
| LocalShell | 无 sandbox backend 时 Sync 只做本地校验；Restore 因缺 sandbox 直接返回 |
| 并发 | Store 读写用请求级 `get_current_store` / `get_current_user_id`，同工具对象多用户不串 namespace |

## 6. 面试记忆点

**SKILL.md 和 `@tool` 差在哪？**  
SKILL：长手册 + 沙箱脚本，落盘同步即可用。`@tool`：宿主固定 schema（如 `install_skill`、`web_fetch`）。

**安装后文件落在哪？**  
宿主 `src/skills/<name>/`、沙箱 `/skills/custom/<name>/`、用户 Store（`skills_store_namespace`）。

**Sync 和 Restore 谁管什么？**  
Sync：宿主仓库技能 → `/skills/`。Restore：Store 自定义技能 → `/skills/custom/`。

**换容器后技能怎么回来？**  
Health `on_rebuild` 调 bootstrap + 两边 invalidate/sync/restore；日常请求靠 before_agent 增量与 generation 兜底。

**收束。** 手册进提示、脚本进沙箱、用户技能进 Store；中间件在每次 Agent 跑前（以及沙箱重建后）把三边对齐。复习时先对节 2 的通道表与时序，再对 3.3 / 3.4 / 3.5。
